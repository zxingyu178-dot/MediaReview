## 用户路径与结论

1. **打开应用、连接电脑**：两套服务的配对隔离已存在；生图连接页仍有Bridge、DataStore、token和能力码等内部术语，用户不容易知道应去哪里拿地址与配对码。
2. **找视频/图片、刷新目录**：媒体/相册分类、直接目录与包含子目录开关已存在；首页下拉刷新圈与请求完成脱节，目录到批阅还需再次选范围。
3. **连续批阅视频**：已有范围确认、会话恢复、拖动进度及Alpha25预取取消；范围选择器有可确认的草稿重置问题，目录多时缺少搜索和层级折叠。
4. **连续审核生图、查看提示词**：已有成功回执后切图、失败停留、新图追加队尾、撤销和按提示词版本评分；后台同步与审核共用busy，图片是否真正显示还未参与审核按钮门禁，原图查看入口未接通。
5. **清理待删除**：已有两阶段确认、实际回执核对、失败不报成功等保护；本轮不改删除链路、不发送写请求或操作真实媒体。

## 长时间使用的资源风险（尚未量测）

`feature/v2/nsfw/data/NsfwFeedStore.kt`用order/byId保存全部已发现条目、snapshot（:93）复制全列表；`NsfwReviewViewModel.kt:858`一次同步最多10页，限制单轮请求数但不限制长期累计条目。随着图片持续生成，元数据、缩略图条目和列表复制成本可能增加；**不能据此称已发生内存泄漏或卡顿**。

后续用隔离的几千条元数据样本测切图/合并开销，再判断是否窗口化；保留当前图、待确认写入、撤销目标、游标与REMOVE修订语义，不能简单按数量截断队列。这比上述文案/状态问题改动更大，单列后续任务。
