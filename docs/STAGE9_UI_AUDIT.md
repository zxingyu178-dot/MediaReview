## 优先修复的问题

### P1：重复媒体、媒体库管理标题与状态栏重叠

截图08、09/10显示标题与时间、通知图标处在同一高度，返回按钮及标题上部受到干扰。相关页面没有处理顶部系统栏，而待删除页面已经使用statusBarsPadding。统一详情页的WindowInsets处理，验证挖孔/刘海、横屏及大字体；不要只给某个机型加固定像素边距。

落点：`organize/duplicates/DuplicatesScreen.kt`、`organize/libraries/LibraryManagerScreen.kt`，对照`organize/delete/DeleteQueueScreen.kt`。

### P1：分类浏览常驻整段技术诊断

截图01把Server版本、API Contract和13项英文capability直接铺在目录上方，能力清单约占当前截图页面高度的一成，连同标题和开关进一步压缩内容区域。普通用户很难从中判断下一步。将完整诊断移入数据源/故障详情，浏览页只保留简洁连接提示与必要错误。

落点：`home/FolderBrowserScreen.kt` 的 RuntimeDiagnosis。首页只有简短版本行，与目录页面的信息密度也不一致。

### P1：目录归属与部分封面故障仍存在

此前完整体检已经用真实元数据和临时库确认409个跨库Item的单一library_id覆盖问题；本轮没有修复它。当前视频列表又出现上游thumbnail 404，被代理为502。能正常播放的视频和能否显示封面需要分别处理；缺封面应有清晰占位，详细请求号可放到可展开的诊断中。

**本轮最初只选择一个库，该库Jellyfin实时总数也为0。** 这次首页为空有当前库选择的合理解释，不能把它再算作跨库覆盖的新复现。临时加选有内容的库后显示媒体，证明空态需要提示范围和修复入口。旧故障证据与本轮状态须区分，见`STAGE9_HEALTHCHECK.md`。

### P2：空态与库选择之间缺少解释

首页“暂无媒体”、目录“此目录暂无媒体”都没有说明当前选中库数、来源/类型过滤、同步状态，也没有“管理媒体库/清除筛选/重试”的直接入口。库管理列表只给名称和复选框，不显示当前媒体数量或上次同步结果。建议在空态展示当前范围，给出一项与原因对应的操作。

### P2：待删除摘要、历史失败及扫描状态文案容易误读

截图07标题说“没有待删除内容”，下方却列出多个历史失败项。最终删除0项并禁用是正确的，但应明确“待处理0项、历史失败N项”，并解释恢复后重新标记的后续动作。整理卡片显示“未发现重复媒体”，详情却显示“尚未扫描”，应区分“尚未扫描/扫描中/完成且0结果”，不把未知当作没有。

### P2：选中状态未进入可访问性语义

截图04的当前来源、排序、顺序、类型有明显青色选中样式，但对应XML节点及控件状态没有selected/checked；`SortFilterSheet.kt`中的OptionChip仅用背景与文字颜色表达状态。应使用可选择语义/角色，让辅助技术能读出当前选中项。底栏图标和文字也有重复标签节点，存在重复朗读风险，但本轮没有开启TalkBack，不能声称完整读屏验收失败。

## 待复核，不算已确定的实机缺陷

- 查看器文字标签和图标是分开的触控结构；一次点击“信息”文字后工具栏消失，后续流程曾被中断并返回首页，尚未完成稳定复现。文字本身无点击处理是源码观察，不能把本次中断归因于App崩溃。后续应分别验证图标、文字及沉浸式返回。
- `ImageInfoSheet.kt`将sizeBytes直接整除1024展示KB，存在未知值被显示为0 KB的风险；本轮未完成信息面板的实机核对，应与删除回执的“未知大小”语义统一后做小回归。
- 播放器打开过渡帧同时看到主页与控制层，可能来自导航动画/首帧加载；未持续测量，不据单帧断言稳定状态透底。

## 验证范围和下一步

本轮复用前次Server全套643通过/4失败/41初始化错误、Android497通过的结果，**没有重跑这些套件，也不将其称为本轮新通过**。新做的是正式Release上的导航、筛选、空搜索、图片显示、视频出帧及截图/语义检查。

未做真实删除、重复扫描、批阅自动标记/断点写入、收藏写入、断网/失效配对、全格式、横屏/字体缩放和TalkBack测试。避免测试改写用户既有批阅进度；没有把这些未执行项计为通过。未部署、未清除Android数据、未操作真实媒体文件。
