## 一、问题与原因边界

当前图库将数量、同步、旧桥说明、批量、继续上次、新图、错误等逐行常驻，图片区域被压缩。看图页使用普通预览，点击后再打开独立原图对话框；双指缩放只有进入该对话框后才可用，对话框也没有连续切图。

后台同步切换文字和增删提示行，会改变布局；底部将不断变化的已加载总数绑定进进度文字。具体闪烁还须以最小场景复现，不能未经验证就归因于所有重组。

最新排序已存在于手机与配套桥源码，但当前日用桥0.13.0缺图库查询能力，手机走旧feed兼容路径。局部反转已加载数据不等于全库“最新”，不作为解决方案。

整理删除的本次实际错误仍待读取和定位，不提前断言是权限、未选媒体库、只读来源或请求超时；保留nonce、根路径、文件身份和回执保护。

## 二、方案取舍

| 方案 | 用户体验与影响 |
|---|---|
| 仅收起现有说明 | 改动小，但仍需点击再缩放，也不能解决两套看图入口的切图分裂 |
| 图库精简＋统一看图（推荐） | 进入图片即可缩放、适屏左右切图；明确手势分工，保留原认证/状态/图片加载能力 |
| 全面重做所有页面 | 改动大，会扩大到已工作的播放器与导航，本次不采用 |

## 三、图库

正常页面只有紧凑工具栏和图片区：标题“生图”，当前排序“最新/最早”，筛选、刷新、更多图标。图标采用现有Material图标；可见图形不使用Emoji代替。触控目标至少48dp，提供中文contentDescription及长按提示。

- 数量以低强调的短摘要呈现，不随着每次后台读取反复改变工具栏高度。
- 日期、状态、分类、收藏、关键词及标签放筛选面板；只有启用的条件显示紧凑标签，支持清除。
- 更多菜单承接9图审核、同版本比较的说明、继续上次、连接诊断等次级入口；批量页面自己的选中与提交状态保持明确。
- 正常同步只在刷新图标内反馈，不新增“同步中…”文字行，不禁用正常浏览与切图。新图提示只在确有新图时出现，使用短按钮“新图 N”。
- 操作说明、旧桥能力说明移到相应菜单/面板；能力不足用短状态“需更新电脑端”，点开才显示原因，不能隐藏真实不可用状态。
- 多个普通错误合并为一条可关闭短提示并提供重试。冲突、删除/审核未知结果等必须核对的状态不能被普通自动消失提示吞掉。

## 四、最新与继续上次

- 默认查询服务端创建时间倒序，显示“最新”；用户可切“最早”。时间相同的顺序由既有服务端稳定游标保证。
- “查看最新”重新建立最新范围；“继续上次”保留原图身份、筛选及范围，二者不混淆。
- 位于最新顶部且未进行选择/看图/确认时，可在安全位置更新；浏览旧页、放大、批量选择和评分期间只提示，不重排当前操作对象。
- 前台复用既有3秒检查与失败退避；这只是检查周期，生成到显示的端到端延迟必须实测。后台不要求常驻，返回补齐。
- 上线必须包含桥能力与版本一致性检查、原工作流备份和ControlHub部署准备；单独装新APK不能宣称此项可用。未经授权不直接覆盖日用工作流或部署。

## 五、统一看图与手势

从图库点图直接进入可缩放查看页，图片适屏显示，信息/操作以叠层呈现，不挤压或反复调整图片布局。

| 动作 | 行为 |
|---|---|
| 双指放大 | 直接缩放，无需先点入第二个原图页；信息和普通底部操作淡出，图片不跳尺寸 |
| 缩回适屏 | 恢复此前可见的信息和操作；使用容差，避免在1倍附近反复显隐 |
| 适屏左右滑 | 仅切上一张/下一张，不产生保留或淘汰决定；确认页提交中不切换目标 |
| 放大后单指拖 | 拖动图片，不意外翻页；缩回适屏后恢复切图 |
| 单击 | 手动显隐信息层 |
| 双击 | 沿用适屏与局部放大切换，焦点跟随点击位置 |
| 系统返回 | 放大时先回到适屏，再返回原图库位置；明确确认/核对层优先按其既有返回规则处理 |

保留/淘汰仍使用图标加短文字的明确操作，不让左右滑动兼任审核；收藏、信息、评分用图标，需确认的动作显示相应目标与结果。提供无障碍上一张/下一张动作，并在更多菜单保留点击切图的备选，避免只有手势可用。

仅当前图片按需读取原图；相邻项有界预取预览，不因Pager预组合下载多张原图。失败保留已解码预览并能单图重试。原媒体播放器和普通相册不随本次改版重构。

## 六、刷新稳定性

- 以图片ID保持当前页，后台元数据合并不重建整页、不重置缩放、不将旧请求结果画到新图。
- 图像区域与操作层使用稳定布局；可见性变化以透明度为主，避免同步过程改变高度。
- 当图片列表没有变化时，不重复滚动缩略条。数量、同步图标、详情加载各自更新，不能作为重建整页的key。
- 当前页“第N张/总数”来自固定查询范围；总数未知就显示“第N张”，不把不断补齐的已加载数量冒充全库总数。
- 当前图片被其他端移除时，明确提示并按既有有效邻项规则恢复；未确认的审核与评分不得被刷新清除。

## 七、整理删除

先只读取得本次队列的失败类型、来源能力及服务版本；不点击真实最终删除来复现。使用可丢弃样本覆盖确认和回执链路，再修复已确认的根因。

界面区分“待删除”“上次失败”“结果待核对”；失败项提供与原因匹配的恢复入口，不能要求用户猜测。只读来源不能显示成可永久删除；库未选中不能自动勾选绕过保护；结果未知不能换nonce盲目重删。精简说明不削弱二次确认和冻结清单。
