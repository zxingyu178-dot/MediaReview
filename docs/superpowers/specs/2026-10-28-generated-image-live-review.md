# 生成图片独立页面及动态队列（用户最新指令）

本文件替代上一版方案中“批阅内来源选择”和“冻结批次”两项。用户要求：与批阅同级的独立页面；生成图片持续追加队尾；每张图可看提示词、生成时间、尺寸，首期以可查看为主。

实现边界：只改MediaReview，NSFW代码/数据/配置/服务均不改。当前8767桥只提供冻结session队列及不含prompt的图片摘要，无法直接兑现两项新增要求。已向用户询问是否有更新合同/分支；未获得前不能假设新端点存在，不能通过反复创建全局会话轮询新图，不能直读上游数据库或暴露8000。

手机侧先建立独立图片模型和稳定追加队列：以image_id去重，已有位置不重排，新发现的图片按本次增量顺序追加；同ID补充元数据时只更新原位，浏览位置按ID保持。元数据明确区分“提示词未提供”与实际空提示词，不伪造。断线/轮询间隔不代表列表删除，只有上游明确的删除/失效事件才标记不可用。

后续独立一级入口命名“生图审核”，图片页面和信息面板使用独立状态，不进入视频播放器或媒体删除队列。新图到达时保留当前观看位置，可提示新增数量，用户到队尾后继续浏览。自动刷新仅在页面前台运行，先追完分页再继续轮询，避免重复请求；不把设备时间当服务端游标。

## 给NSFW维护者的最小接口需求（提案，不是已存在接口）

1. 通过现有8767/Bearer边界提供图片增量发现：稳定image_id、服务端不透明游标、分页has_more/next_cursor，明确首次加载范围、并发生成、相同时间戳、删除/失效事件和游标过期的恢复语义。每页至少携带created_at、尺寸、三档图片相对URL、审核状态及updated_at。不要求开放生图/模型/工作流管理。
2. 图片详情按image_id提供生成时保存的提示词（正/负向若存在）、生成时间和尺寸；未保存字段明确nullable，不能用当前可编辑Prompt库内容冒充生成时快照。可选seed、模型/模块、job_id、文件大小、MIME；缺失需明确，不作为首期强制字段。
3. 现有decision依赖冻结session项。动态新图如何审核须确认：新增按图片ID的审核合同，或提供安全的session尾部追加及相应全局index/total/seen语义。不要客户端自行猜测未入会话的image_id可直接decision。

当前工作先交付可独立验证的手机队列基础；独立页面实际联通、持续新图和完整提示词展示需要上游合同后继续完成，不把基础提交算全功能完成。
