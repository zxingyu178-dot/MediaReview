# 删除可靠性、界面体验与生图接入准备（已获用户确认）

基线：feature/mediareview-local-only / e0def77；正式Alpha21/code28、Server1.6.3。根据已读代码及前轮真机证据规划；本轮不连接手机。仅修改MediaReview，不修改NSFW，不追加真实删除测试。

## 推荐顺序与方案

先解决删除结果不确定，再做有限UI打磨，最后准备生图客户端接入。仅延长HTTP超时改动较少，但无法解决断线后回执丢失；引入独立任务服务代价过大。本轮推荐复用现有Server和SQLite，把删除处理移出事件循环，并提供可查询的持久结果，不新增长期服务。

## 1. 删除闭环

现象：第一批31项审计跨度20.374秒，Android readTimeout15秒，文件已删除但手机未得到结果。当前async路由直接执行同步删除；结果对象仅随本次响应返回，nonce已用之后仅返回409。

方案：保留prepare、快照、二次确认、一次性claim、文件身份及路径检查。删除工作使用框架既有执行机制，数据库会话由执行单元独立持有，不跨线程并发共享。列表刷新不得把仍在执行的删除错误地当成中断恢复；新增结果查询前必须解决执行中与恢复中的互斥。

按批次保存逐项结果和真实成功删除字节数；查询只读回执，绝不重新执行删除。客户端确认后显示“正在处理”，超时后进入“正在核对结果”，以有界退避查询同一批次；恢复页面可继续查询。成功、原本不存在、失败、处理中、结果未知分别显示。缺少可信删除事实时保持未知，不从队列消失或历史文件大小推断成功。

实施前审查现有迁移/审计能否完整表达结果。若必须增加列或表，采用小型版本迁移，并明确旧nonce无回执、升级备份和回滚兼容边界。结果查询必须认证并绑定提交身份；不能因客户端提交任意nonce泄露其他设备批次。旧客户端保持兼容，新客户端探测能力后才使用结果查询；旧Server仍展示明确的结果未确认提示。

验收：可丢弃临时文件正常删除、missing不计空间、失败不报成功、越界拒绝、并发/重放不重删；慢删除期间健康请求可响应；响应丢失后可查询原结果；进程中断后不虚报字节数。只运行关联安全/接口/JVM测试。

## 2. UI与体验

保留视频/相册和上下切片、横向seek交互，不重写播放器。优先删除页：摘要与按钮数量一致，历史失败与待处理明确区分；处理中的按钮状态和完成回执可见；列表刷新失败保留原内容并提供局部重试。

其次检查首页、相册、目录选择、整理页：首次加载、后台刷新、真空列表、网络错误分别表达；统一按钮高度/间距/危险操作颜色，检查长文件名、大字体、底部系统栏和窄屏下的遮挡。已有独立卡片重试机制复用，不另建状态框架。

验证使用Compose预览/已有离线测试及必要编译。是否运行模拟器另依当前用户偏好，默认本轮仅离线检查；没有渲染证据的项目标为静态检查，不宣称视觉或真机验收通过。

## 3. 生图接口准备

沿用已确认的独立“生图审核”一级入口及GeneratedImageQueue；先建立仓库接口、可空详情模型、能力状态、分页/增量控制器、评分目标和值校验。生成时间、尺寸、提示词快照缺失时显示未提供，不伪造。新图去重追加队尾、旧图原位更新、当前位置按ID保持；只在页面前台追增量，遇空轮询不清空。

独立连接状态与凭据存储，MediaReview视频服务token不发往生成桥。图片URL只允许已配对的桥同源；上游未支持时呈现“当前服务尚未提供此能力”，不虚报空队列或写入成功。

提示词评分目标是prompt_id + prompt_version_id，多张图共享该版本评分；单图审核与提示词评分独立。总分1–5，可选维度不默认填值；无可靠归属时禁用写回。模型与Repository先准备，HTTP路径/字段映射仅在上游合同确认后启用。既有NSFW_MOBILE_API_REQUEST_V2.md仍是提案，不把提议端点硬接生产、不自动探测写入、不反复创建全局session冒充增量。

验证：合成数据分页、去重、尾部追加、原位更新、游标失效和错误状态；详情未知字段；版本评分对象隔离；凭据及图片源边界。测试数据不加入Release资源。

## 交付边界

各项串行、定向测试，保持GitHub同步。源代码完成不等于正式包已部署；新版本须更新唯一发布入口。只在有必要验收的Android改动完成后构建一次APK；本轮不安装手机。生图HTTP联通、手机视觉交互与长期网络稳定性单独列为未验证。
