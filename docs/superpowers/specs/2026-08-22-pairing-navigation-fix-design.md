# 配对成功后导航修复设计

日期：2026-08-22

## 问题

Android 客户端收到配对成功响应并保存服务器地址、设备 ID 与令牌后，只把 `ConnectUiState.paired` 更新为 `true`，没有触发连接页已经提供的 `onContinue` 回调，因此界面停留在配对页。应用重启后虽然能恢复已配对状态，但根导航仍固定从连接页开始，同样不会进入首页。

数据库中的三条设备记录并非手机重复创建：两条为已撤销的 `codex-smoke-*` 部署测试记录，一条为当前手机的有效 UUID 记录。本次不删除历史记录，也不调整服务端计数语义。

## 修复范围

- 连接页观察 `ui.paired`。
- 当状态变为 `true` 时调用现有 `onContinue`，由现有导航逻辑进入首页并从返回栈移除连接页。
- 该行为同时覆盖刚完成配对和启动时恢复已保存配对两条路径。
- 不修改配对协议、令牌存储、服务端数据库或媒体业务功能。
- Android 版本更新为 `versionCode 4`、`versionName 1.0.0-rc2`。

## 实现方式

提取一个最小的、可在 JVM 单元测试中验证的配对导航决策函数。Compose 页面在 `LaunchedEffect(ui.paired)` 中调用该函数；未配对时不导航，已配对时调用一次 `onContinue`。使用 `ui.paired` 作为 effect key，避免普通重组反复触发。

## 测试与验收

先添加失败测试，再写生产代码：

1. `paired=false` 时不调用导航回调。
2. `paired=true` 时调用导航回调。
3. 运行 Android JVM 单元测试。
4. 构建 Debug APK。
5. 检查 APK 的包名、中文应用名、版本号和签名信息。

真机验收标准：输入有效配对码后自动进入首页；强制结束并重新打开应用后，也自动进入首页。
