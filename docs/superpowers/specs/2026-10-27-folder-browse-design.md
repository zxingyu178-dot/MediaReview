# 文件夹分类与排序整改（用户已确认）

用户选择“文件管理器”方案：保留当前目录直接图片和视频，子文件夹独立在前；默认不混入深层媒体，可显式开启包含子文件夹。没有选择隐藏直接媒体或继续默认递归混排。首页“全部/最近”仍是全库媒体墙，不改真实磁盘分类或移动文件。

已确认缺陷：FolderBrowser默认递归、缺排序入口；请求借用首页sortSpec，目录没有独立排序/类型选择；根视图单库展开后递归重复其子目录内容。整改只涉及Android已有文件夹浏览链路，Server1.6.3已支持include_descendants=false、分页排序和类型筛选，无需新增接口或部署。

设计：文件夹页常驻“全部/视频/图片”及排序摘要入口，复用既有排序面板（最近添加、文件名、时长、大小，正倒序），不显示无关的跨来源选择。目录默认文件名正序、全部类型、仅当前目录；设置在同一ViewModel内跨目录/进入媒体后返回保持，并与首页独立。子目录始终可进入，不因媒体类型筛选而消失；名称排序时跟随正倒序，其余媒体排序下子目录固定名称正序。目录卡明确递归总数/直接数，页面标明范围和当前筛选结果数，避免把0项误认为整棵目录为空。

单库分类根显示其子目录及根内直接媒体，哪怕没有子目录也不漏根内文件；多库分类根只列库，进入库后可见其直接媒体。媒体分页沿用每页50、generation取消和现有缓存键，排序/类型/递归范围切换隔离窗口与锚点，旧响应不覆盖新结果。打开图片/视频仅使用当前已加载同类型窗口，携带目录实际排序，不能误用首页。

验证：最少JVM回归覆盖默认直接范围、切换排序/类型后的分页与旧响应、根层级和队列上下文；现有Compose设备夹具覆盖目录点击、图片/视频切换、排序后分页、递归开关和返回。只在隔离模拟器使用合成媒体；手机若可用再做只读抽样。产物为同证书Alpha20/code27独立APK；Server不重建、不升级，无真实删除或数据迁移。不运行全量connected/JVM/Server。
