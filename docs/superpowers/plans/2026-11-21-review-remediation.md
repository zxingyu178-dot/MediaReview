# MediaReview 审查整改计划

基线：codex/core-flow-polish，4bcdf64。审查报告涉及发布、连接、目录、批阅、安全与产品范围。先锁定发布证据并修复有明确兼容边界的缺陷，性能改造按实测分段实施。

| 报告项 | 评估与验收 |
|---|---|
| 1 发布漂移 | 优先。先校验运行态、构建输入和历史包 Git HEAD。准备独立 Server 1.6.8 候选，包含迁移 0019 和 pairing_check_v1。独立发布 Android。发布清单绑定提交、版本及文件哈希。发布指针只在明确的发布验收完成后更新。正式升级和回滚另按 ControlHub 及项目权限执行。 |
| 2 误判离线 | 优先。新服务已有轻量探针，旧版回退仍读媒体页。已核对正式 1.6.6 源码 `c86ece4` 有受认证的 `GET /tasks?limit=1`，可作为低成本回退的候选。先测响应、查询计划和旧版兼容，再覆盖 401、慢请求与断网，保留凭据验证边界。 |
| 3 同步 | 实用。先核对 refresh 的目标范围和任务回执，再补手机触发、进度及终态刷新。新选库自动同步须测重复触发、取消和容量。保留“刷新列表”和“同步索引”的不同语义。 |
| 4 目录 | 优先实测。以 0019 为基线，拆分树构建、缓存失效、分页和封面。先复现元数据或空更新清树，再按目录依赖缩小失效范围。按库聚合、持久 ID 和旧平面分页需有收益证据，保留路径归属契约。 |
| 5 封面 | 先测扫描并行时首封面、队列等待与数据库写。再决定有限并发或占位反馈。无变更 UPDATE 涉及锁与身份校验，替换前必须测竞态。 |
| 6 返回重拉 | 真实浪费。先记录首页、目录、相册的真实请求数，再做有界校验。首尾页、插删、排序改变、滚动锚点和源切换必须验证。只刷新第 1 页后直接拼旧页可能重复或漏项。 |
| 7 日期 | 独立修复。服务端媒体时间输出明确 UTC，客户端兼容旧服务端无时区值，同时保留显式偏移。用接口序列化和 Android 合同测试证明。 |
| 8 批阅计数 | 目前缺少 `(session_id, index)` 索引。可独立新增普通复合索引，保留现有 `(session_id, media_id)` 唯一约束。测查询计划和长队列成本后再定迁移。位置写入与审核计数分开测。跨设备、advance 和完成行为需确认产品契约。 |
| 9 删除 | 已确认旧入队接口对任意既有队列状态返回同一个 409，包括已有失败记录。客户端须按回读状态判断，或由新版接口区分；不可把所有 409 当成功。失败分区、重新排队、权限诊断优先于重写执行。异步删除必须保留 nonce、队列代次、身份复验和回执，使用隔离样本。 |
| 10 收藏失效 | 保留收藏身份，用明确的可用状态区分缺索引、离线和权限。验旧服务、失效显示及取消收藏。 |
| 11 重复整理 | 可做。批量加入待删除前显示范围与选中保留项，验证非整组成功时的逐条结果。正式删除仍走已有流程。 |
| 12 批阅语义 | 属于产品设计。视频批阅、生图审核、普通图片批阅分开确认。保留、已看、稍后看和重新批阅的持久化含义确认后再改。 |
| 13 安全与隐私 | 优先验证配对限速、撤销授权与远程路径收口。只使用隔离设备与合成数据。HTTPS 和地址变更不能把旧凭据送到未经核验的新主机。 |
| 14 生命周期 | 先量化库体积、增长及保留要求。归档与清理应尊重历史回执和审计，清理真实数据前单独确认。 |
| 15 文件夹身份 | 先迁移映射原型并验证收藏封面和续审。保留旧 ID 的兼容读取，避免一次改动割裂历史引用。 |

## 执行顺序

1. 核对旧包来源、版本和发布入口，纠正过期部署说明。开始可独立回归的日期修正。
2. 收口候选构建和部署验收门禁，再联测轻量连接、同步和目录。生产操作需明确授权。
3. 根据实测减掉返回重拉、封面串行等待和批阅计数成本。
4. 处理删除失败、失效收藏与重复整理。安排安全与隐私复测（13），优先核验配对、撤销和路径权限，设置入口、动效、大字及错误反馈纳入任务走查。
5. 目录性能验证后，以只读方式统计数据保留成本（14），原型验证双文件夹身份迁移（15）。数据归档、旧 ID 迁移和回滚需单独验收。
6. 自动发现／二维码、跨会话审核、普通图片批阅和私密入口作为产品能力单独定范围。保留已确认的视频首页与独立生图入口，除非用户明确同意调整。
7. 更新当前状态、部署指南与规格，分别记录单元、隔离集成、模拟器、真机及正式运行证据。

## 发布证据

- 主工作区存在正式交付清单，指向 Server 1.6.6 / 0018 和 Alpha34 / code41。开发 worktree 缺少其本地副本。
- 开发 worktree 的历史 1.6.7 ZIP 内嵌发布清单记录源提交 `75266cb` 和 Alpha37 / code44。源提交的数据库迁移止于 0018。当前分支的目录索引迁移和探针能力来自后续提交 `8a50413` 和 `4bcdf64`。
- Server 1.6.8 与 Android Alpha47 / code54 是本轮源码目标。Server ZIP 清单只记录 Server 产物。独立 APK 采用自己的版本、签名验证和哈希清单。正式指针始终从主工作区读取。候选产物、正式安装和回滚分别验收。

## 手机体验验收

- 连接与工作状态：首启配对、选库、等待同步、慢请求、断线、过期凭据各有准确反馈和可执行入口。二维码与地址迁移先明确凭据绑定和旧版兼容。
- 浏览与批阅：核对“最近”与实际排序、当前目录与子目录范围、长列表续页、已加载内容返回复用、完成和索引为空的区别。用慢网络走一遍收藏和生图撤销，观察焦点、滚动位置、加载和失败重试。
- 设置与可访问性：版本、连接诊断和待处理异常易找到。实测 320dp、200% 文字和 TalkBack 的主要任务，覆盖空态、错误态及删除确认等弹层。生图进度缺少桥能力时在设置提供简短说明，图库保持简洁。
- 待产品确认：混合首页、更多列数、独立图片批阅、跨会话审核状态、共享手机的生图入口和访问保护。APK 瘦身留到播放、反射与安装兼容能独立回归时评估。

## 首轮执行结果

- 日期兼容已进入源码。服务端为媒体时间补明确的 UTC，Android 将旧版无时区值解释为 UTC。回归覆盖旧值、显式偏移、缺失与无效值，兼容旧版日用服务。
- 首轮门禁只校验 EXE 自报能力与空库迁移头。复审改为在开启配对要求的隔离 EXE 上调用探针，验证 401／200，并在进程退出后核验 0018 合成库升级、数据保留和源码 Alembic head。运行中的正式库、正式升级失败回滚与 SCM 生命周期另验。
- 100k 合成媒体 API 用例三页通过，旧平面 `GET /media/folders` 处理约 3.1 秒，超过 2 秒硬上限。同一数据库的 100k 行均无路径，提前过滤路径后的对照仍为约 2.2–2.5 秒，未保留改动。查询计划仍选按可用性扫描的索引，下一轮应分别比较无路径、少量路径和大量有效路径时的索引计划，保持媒体跨库归属正确。

## 第二轮审查处置

| 复审项 | 结论 |
|---|---|
| 1–2 日期契约与测试 | 核心媒体、同步、批阅、删除、重复扫描、任务、设备与媒体源的 API 时间统一为 UTC。HTTP 回归覆盖两项非空媒体日期经过列表、详情、收藏、待删除和审核队列，以及同步与审核时间。 |
| 3–5 旧格式与复现 | 旧 MediaReview 将 SQLite 日期编码为带 `T` 的 ISO 8601。客户端也容忍空格分隔的时间，纯日期按未知处理。历史 Jellyfin 无偏移值来源不可从 SQLite 逆推，维持已有约定。Windows 复跑使用工作区内的短、可写 `--basetemp`，未取得复审方 SQLite 失败的完整路径。 |
| 6–8 版本与产物 | 源码目标升为 1.6.8 / Alpha47，更新说明和版本合同已同步。当前打包流程将 APK 导出为独立文件并生成独立元数据。历史重打包继续核对原包来源和哈希。 |
| 9–12 二进制门禁 | 已构建并验证隔离 Server 1.6.8 EXE。真实 HTTP 401／200、0018 合成数据升级保留和停机后只读核验通过。目标迁移从 Alembic 源码读取。正式 Windows 服务的升级失败回滚是部署链的独立验收项。 |
| 13–14 红项 | Windows SCM 用例仍遇 PowerShell 执行拒绝。PowerShell 只读包校验接受新版 Server 包结构。100k 目录性能保留红项。复跑实际 SQL 的 `EXPLAIN QUERY PLAN` 显示先用 `ix_media_cache_available_type_global_resolution` 按可用性扫描，再做两次关联媒体库归属查询，物化后还需要两次临时排序。后续分别验证有路径和无路径分布的索引方案。 |
| 15–20 计划与工作区 | 明确独立复合索引、补充 13/14/15 排期，修正候选措辞。计划与状态文档同提交。生产发布指针以主工作区为准，开发 worktree 的历史包不能作为当前发布入口。 |

旧 Server 连接降级、手机同步入口、目录缓存、封面队列、返回重拉、批阅性能、失败队列与失效收藏仍进入原计划。历史失败数量需另作只读复核。二维码、独立设置、入口保护和跨会话审核需先确认产品契约。
