## 1. 目录缺视频：已确认的功能缺陷

用户停留的子库目录在手机显示空。只读 Jellyfin API 返回该库101个视频，SQLite却没有归属该库的条目；101项全都存在于父级媒体库的索引。另一个库同样有294项被归入父库。经手机从父库进入相应子目录，实际翻页到底显示“已加载全部101项”，表明这批视频并非文件丢失或分页只能取50项。

根因位于 `server/app/services/media_index.py` 的 `upsert_media_items()`：稳定媒体ID按Jellyfin Item ID派生，缓存行仅有一个 `library_id`，冲突更新直接覆盖该字段。Jellyfin允许同一Item同时由父库和子库返回，后同步的库会覆盖前一个库的归属。目录树和媒体查询均按这一单值过滤，因此子库为空。临时可丢弃数据库已复现：先同步子库得到1项，再同步父库的同一Item，子库变为0、父库为1。

逐页只读对账了全部21个Jellyfin库：当前16勾选、5未勾选，未替用户改动。上游去重56,566项，缓存同为56,566项，但**不能仅凭总数相同判断同步正确**：409个不同Item跨库重复出现，另有2项仅在上游、2项仅在缓存。后者未确认是新增/删除/重建ID还是同步陈旧；已记录为独立差异。同步成功时间记录停留在此前批次，本轮没有触发全量刷新。

修复建议：保留稳定媒体主键和既有收藏/批阅/删除关联，增加媒体与库的多对多成员关系，查询和目录统计使用成员关系；同步按库更新成员，不能因一个库不再包含媒体就全局隐藏。该修复需要小幅数据库迁移及备份/回滚验证，不应靠复制媒体行、更换稳定ID、隐藏空库或重复扫描掩盖。还需覆盖“父子库同Item、选择任一库仍可见、全局去重、单库取消/刷新失败、删除后全部成员一致”的回归。本轮未执行迁移。
