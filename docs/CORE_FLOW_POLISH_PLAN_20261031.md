# 核心流程继续打磨

基线e253aa0 / Alpha26。上一轮为有效进展，当前目标“继续打磨，直到成为合格产品”保持进行中。本轮不重新定义产品合格为某组测试通过。

- 相册SQL：隔离5万条索引、296目录、24库复现摘要约2.1秒、目录定位0.76秒、分页1.27秒。只改查询形状，复用现有索引；EXISTS归属过滤让有序分页避免先物化全部ID，目录计数/图片数/最新图片合并为一次窗口聚合。试验摘要约1.13秒、分页0.35秒；单库也对照，不用单次基准证明真实电脑性能。保留多库去重、旧记录无membership时的兼容、失效membership拒绝回退、筛选与封面排序。无数据库迁移。
- 批阅范围：重复打开/重试保留当前草稿和包含子目录开关；缺失目录明确阻止开始，不能把失效范围自动变成全部视频。取消再打开仍从实际会话范围初始化。
- 生图同步：只读syncing与写入busy分离；一次只读同步，有界分页及游标恢复不变。旧增量不得覆盖新审核回执，读失败/取消不得放开仍在提交的写入；换连接后旧回包不得影响新状态。离页取消手动读取和轮询。
- 误操作与反馈：解除生图配对移入更多菜单并说明后果、确认；视频列表刷新指示跟随请求，取消/切页正确结束，不再固定700ms。
- 验证：先补现有API的最小故障回归；Server按查询/归属/相关删除安全边界定向pytest，Android两个相关ViewModel及必要状态/版本检查。重型进程串行；已有Alpha26证据复用。源码/测试收口后再统一生成Alpha27与必要的Server1.6.5产物，版本、签名、唯一入口、Git同步准确记录。部署与真机行为分别验收，不读取/删除真实媒体，不改NSFW。
