# 图片、视频与预览加载调查（2026-10-27）

## 范围与结论

调查基线 `4412e81`，Android Alpha17/code24、源码 Server1.6.1；生产上次实测仍为1.5.2。本轮只读源码、Git历史和开源资料，未修改程序、部署、刷新真实库或播放真实媒体。没有新的手机性能数据，不能宣称已解决慢加载或给出提速百分比。

优先顺序：**恢复核心雪碧图预览 → 统一图片缓存与可见项调度 → 测量并缩短视频首播链 → 有界预缓冲下一条内容**。沿用现有播放器和Server，不部署额外媒体服务。

| 图片缓存复用 | 预取使用默认内存键，`MediaThumb` 使用 `coverUri:profile:retry`，相册、文件夹又有其他前缀。查看器的占位键也未统一；这些路径无法按同一键直接复用已解码位图。磁盘/HTTP缓存仍可能命中，不能据此断言重复下载。已有共享Coil ImageLoader和缩略图尺寸档位，应修复复用关系而非再造加载器。 |
| 大图 | `ZoomableImage.kt` 已有小图渐进展示；`OriginalImageRequests.kt` 限制解码2048，相邻原图在当前成功后预取。Server `/original` 流式传输完整原图，客户端解码尺寸不会减少传输字节。原图内存缓存禁用有校验语义，不能简单全部打开。 |
| 视频批阅 | `V2ReviewViewModel.kt` 当前稳定播放后预取相邻播放地址、封面，没有缓冲下一条视频数据。`cacheWithPlay=false` 未开启GSY磁盘缓存，但不代表播放器没有内存缓冲。 |
| Jellyfin首播地址 | `media.py` 在返回可直连URL前依次等待凭据、PlaybackInfo及续播位置。存在串行关键路径；各步实际耗时尚未测量。下一步评估必要信息优先返回、非必要补充延后，保留鉴权、地址安全及回退语义。 |
| Server图片缓存 | `thumbnail_cache.py` 的异步入口仍同步读写文件；成功请求有同键合并，异常不作短期负缓存，缺封面可反复访问上游。生产1.5.2未含图片404分类修复，源码1.6.1已含，尚未部署。 |
| 本地缩略图/雪碧图 | `native_images.py` 未命中时可等待20秒、每150ms查询任务。`tasks.py` 单循环按创建时间取任务，并等待当前任务完成，没有交互预览优先级。`sprite.py` 当前只支持Jellyfin来源；本地源需要在既有安全文件访问层补适配，不能仅恢复Android入口便声称全部可用。 |

历史 `review_meta/ops-20261023/image-perf-report.md` 曾记录目录请求2.6–3.1秒、最慢11.5秒，以及53次缩略图上游耗时超过5秒。这是旧版历史证据，**不是当前Alpha17实机基准**；其中锁问题已有阶段修复，不据此重复认定根因。目录SQL、磁盘及上游各占多少时间仍需分段计时。

## 开源策略及适配边界

- **Immich**：缩略图作为初始图，再加载预览，按设置加载图片原图；无监听者时取消请求。适合我们补齐“墙上小图→屏幕预览→需要时原图”，先恢复缓存占位复用。参见[图片Provider源码](https://github.com/immich-app/immich/blob/main/mobile/lib/presentation/widgets/images/remote_image_provider.dart)。
- **Coil**：官方示例用前一次请求的实际 `memoryCacheKey` 为详情页同步占位。我们应统一带认证命名空间、媒体版本、尺寸档位的键，并验证列表/预取/查看器共享命中，不能把不同用户的内容混入同一键。参见[官方Recipes](https://coil-kt.github.io/coil/recipes/)。
- **Media3**：按距当前项的距离设置预加载阶段及内容范围，当前附近优先；预加载器和播放器必须共享所需组件。项目虽依赖Media3 1.10.1，但由GSY 13.2.1封装，需核对对应版本及接入点，不能直接照抄最新版API。参见[官方预加载说明](https://developer.android.com/media/media3/exoplayer/preloading-media/preloadmanager/create)。
- **thumbfast/mpv**：按需生成小尺寸预览，可设置懒启动和空闲退出。借鉴其按需、低分辨率原则，先显示已有封面/缓存预览，再生成需要的帧；不引入mpv服务、不全库批量FFmpeg。参见[项目与配置](https://github.com/po5/thumbfast)。

## 建议的小步实施

1. **恢复预览闭环**：参考历史实现，仅回接卡片长按、单一活动预览、已有清单/生成接口；滚动、切页、退出取消等待。缓存立即显示；首次生成明确显示状态、失败和重试，不要求用户等完整视频处理却无反馈。Jellyfin与本地源支持边界显式区分；本地适配单列最小任务，不能绕过路径/文件身份检查。
2. **图片优先修低风险浪费**：统一缓存键；可见区域优先、随滚动取消过期预取；保留小并发预算。缓存文件I/O移出事件循环。只对已确认缺图设置有界、短TTL负缓存，不缓存认证失败为缺图，不把5xx永久缓存。中尺寸预览是否新增，等完整原图传输量与需求数据后决定。
3. **视频先测后缓冲**：记录地址解析、上游响应、准备、首个实际画面各阶段；避免将“地址返回”或“时间轴前进”当首帧成功。随后仅对下一条做小范围内容预缓冲，当前播放优先、滑走即取消，校验Range/鉴权/撤销及GSY共享数据源；不启动多个全播放器抢带宽。
4. **任务调度最后做必要小改**：交互预览与长扫描不应无区别FIFO；先测排队和生成耗时，再决定限额优先级或独立执行槽。线程数量、缓存容量和FFmpeg并发不盲目加大。

## 如何验证，及本轮未执行项

每个改动只加最小回归：内存键一致/账号隔离；快速滚动取消；缺图TTL到期、认证失败不被隐藏；预览只活动一项、取消不复活旧项；下一条缓存不抢当前且不越过鉴权。复用现有测试，不重跑全套638/488/178。

隔离模拟器用可丢弃合成图片、短视频与可控延迟接口，比较冷/热缓存、连续切换与快速滚动。记录请求数、下载字节、缓存来源、首个可用小图、实际首帧、预览就绪的中位数和P95，以及取消后浪费字节；同一场景前后对照。模拟器可经 `10.0.2.2` 访问宿主机，能验证协议和调度，不能代表手机Wi-Fi和硬件解码；此前goldfish Surface异常下视频出帧未确认，不能把它当性能通过。
